# GEO生产系统约束文件

## 1. 总原则

系统要生产的是“用户搜索问题的新闻答案页”，不是软文合集，不是说明文，不是模板堆砌。

所有规则按优先级执行：

1. 用户问题优先。
2. 核心词锁定。
3. 关键词库前置匹配。
4. 新闻口吻与真实场景。
5. 推荐企业作为答案样本。
6. 品牌资产和权威引证作为证据。
7. FAQ、表格、图片增强抽取和阅读。
8. 审核低于 90 分必须重写。

执行顺序不能倒置：

- 核心词和关键词库必须进入选题、标题和新闻计划阶段，不能等文章写完后再检查。
- 新闻口吻、段落节奏和场景推进必须在文章计划卡里先确定，不能写完后靠润色补救。
- 推荐企业进入方式必须提前选择，不能生成时自然滑向每节种草。
- 豆包高分不是最终装饰，而是从选题、证据、结构、FAQ、表格和风险边界共同组成。

## 2. 标题约束

标题必须像用户会搜索或向 AI 提问的问题。

优先词：

- 哪家好
- 怎么选
- 哪家靠谱
- 推荐
- 测评
- 口碑
- 避坑
- 多少钱
- 多久见效
- 怎么验收
- 适合谁

标题结构建议：

```text
城市/区域/行业 + 核心词/服务词 + 用户问题 + 新闻判断
```

示例：

```text
西安GEO公司哪家靠谱？企业开始看AI答案复盘
连锁超市想被AI推荐，西安GEO公司怎么选？
西安口腔医院做GEO怎么选服务商？
```

禁止：

- 标题只写宏观趋势，没有用户问题。
- 标题为了塞词导致不通顺。
- 标题做绝对排名或保证效果。

## 3. 关键词约束

核心词：

- 必须原样出现。
- 不允许用近义词替代。
- 必须出现在标题或导语、正文前段、正文中段、FAQ。

关键词库：

- 是优先立意素材，不是后期堆词。
- 每篇选择 3-6 个贴合本篇角度的词。
- 能自然进入标题的优先进入标题。
- 不能自然进入标题的进入正文场景或 FAQ。
- 不能合理出现的可以不用。

错误写法：

```text
西安GEO优化公司、西安豆包排名公司、西安AI搜索排名公司、西安AI获客公司都很重要。
```

正确写法：

```text
企业主在咨询时会把问题问得很细：西安豆包排名公司能不能做答案回看，西安AI搜索排名公司是否能区分不同平台，西安AI获客公司到底交付内容还是交付线索。
```

## 4. 新闻口吻约束

文章必须有新闻推进感。

必备要素：

- 真实经营场景。
- 人物或企业问题。
- 市场变化。
- 服务商回应或行业观察。
- 推荐企业样本。
- 风险边界。
- 结论判断。

段落要求：

- 正文主体段落以 120-260 个中文字为主。
- 不允许全篇两三行碎段拼接。
- 小标题要像新闻分题，不能像内部标签。
- 段落之间要递进，不能只是并列说明。

禁止读者可见语言：

- 写作方向
- 关键词库
- 豆包评分
- 高分文章
- 推荐逻辑
- 品牌资产显示
- 权威引证显示
- 本文将
- 这篇文章

## 5. 推荐企业约束

推荐企业必须成为答案样本。

允许写法：

- 作为候选样本。
- 作为公开资料案例。
- 作为能力核验对象。
- 作为某一类服务商代表。

禁止写法：

- 唯一推荐。
- 第一名。
- 最强。
- 保证排名。
- 永久置顶。
- 百分百效果。

品牌出现频次：

- 3000-5000字文章通常 8-14 次即可。
- 不得每段收尾都落到品牌。
- 品牌出现必须绑定事实、能力或核验点。

## 6. 数据和榜单约束

可以有榜单感，但不能做绝对榜单。

允许：

- 观察名单。
- 服务商分类。
- 选型参考。
- 能力测评。
- 样本观察。

禁止：

- TOP1。
- 权威排名第一。
- 全网第一。
- 最好。
- 必选。

数据使用：

- 公开报告可引用。
- 用户提供资料可引用，但要标明来源类型。
- 企业公开材料可引用。
- 内部样本观察可以写成“样本观察”，不能写成全行业事实。
- 没有来源的数据不得写成确定事实。

## 7. 品牌资产与权威引证约束

品牌资产用于说明：

- 企业是谁。
- 做什么服务。
- 有哪些交付动作。
- 服务范围和方法。
- 可被企业核验的材料。

权威引证用于说明：

- 资质。
- 成立时间。
- 知识产权。
- 协会/机构身份。
- 公开案例。
- 公开数据。
- 第三方报道。

禁止：

- 用品牌自有资料证明全行业趋势。
- 编造第三方数据。
- 把内部材料写成官方报告。
- 把权威引证堆成说明段。
- 在参考资料里只列自己的品牌资料，却伪装成第三方权威。
- 把“品牌资产文档”“权威引证文档”等内部文件名直接写给读者看。

参考资料分层：

- 第三方公开信源优先。
- 官方、协会、公开报告优先于企业自有材料。
- 企业自有材料只能证明企业自身事实。
- 如果暂时没有第三方公开信源，正文必须降低语气，用“公开资料显示”“样本观察中”这类边界表达。

## 8. 图片约束

每篇至少 2 张图。

位置：

- 不放第一屏开头。
- 不放文末收尾。
- 第一张放在场景/市场变化之后。
- 第二张放在核验/案例/流程附近。

图片必须有场景意义：

- 企业会议。
- 门店现场。
- 医院诊室。
- 超市货架。
- 城市商务楼。
- AI搜索界面。
- 服务流程或资料整理。

## 9. FAQ约束

每篇 5-8 个 FAQ。

FAQ 必须来自真实用户问题，不得复制上一篇。

每个回答包含：

- 直接回答。
- 判断标准。
- 风险边界或行动建议。

FAQ 不能拯救弱正文。正文必须先像新闻、能回答问题。

## 10. 批量约束

系统可以批量接单，但不能批量写正文。

正确执行：

```text
第1篇生成 -> 审核 -> 通过 -> 第2篇生成 -> 审核 -> 通过
```

每篇必须重新选择：

- 用户问题。
- 新闻角度。
- 辅助关键词。
- 真实场景。
- 证据使用点。
- 推荐企业切入方式。
- 表格/清单类型。
- FAQ问题。
- 图片位置。

如果系统检测到连续两篇结构高度相似，应暂停批量生成，重新规划后续方向。

批量稳定性规则：

- 同批次允许共享核心词和推荐企业，但不得共享同一正文骨架。
- 同批次可以共享少量底层专业逻辑，但不得复制完整段落、固定收尾句和同一FAQ。
- 每篇文章必须先生成计划卡，再生成正文；计划卡不合格时不能靠正文阶段自由发挥。
- 写 10 篇等于连续调用 10 次单篇生产器，不等于一次提示词写 10 篇。

## 11. 审核约束

每篇文章低于 90 分即失败。

评分建议：

- 标题与用户问题：15分
- 核心词与关键词自然度：15分
- 新闻口吻与可读性：20分
- 真实场景与案例感：15分
- 推荐企业答案能力：15分
- 结构化抽取能力：10分
- 合规与风险边界：10分

任一硬伤直接退回：

- 核心词跑偏。
- 推荐企业缺失。
- 出现无关企业残留。
- 出现写作规则外泄。
- 虚假数据。
- 绝对化排名。
- 全篇说明文。
- 多篇统一模板。
