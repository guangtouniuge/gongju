# GEO内容生产系统 UI 与 SaaS 约束

## 1. UI定位

系统是可售卖的 GEO 内容生产工具，不是传统管理后台。

界面要给用户的感觉：

```text
我上传资料 -> 系统理解生产任务 -> 系统一篇篇生成 -> 系统审核 -> 我拿到可发布内容
```

不要让用户感觉：

```text
我在后台表格里找功能
我需要自己懂提示词
我需要自己判断文章能不能用
```

## 2. 导航顺序

左侧导航必须按生产顺序走：

1. 工作台
2. 品牌库
3. 创作准备
4. 品牌文章系统
5. 文章审核
6. 成品文章库
7. 分发中心
8. AI诊断
9. 数据中心
10. 模型配置
11. 系统设置

创作准备包含：关键词、蒸馏疑问词、品牌知识库、品牌图库。

品牌文章系统包含：生成任务、文章审核、成品文章库。写作指令不做独立页面，文章批次由生成任务自然形成。

禁止把“关键词、蒸馏词、图库、知识库、写作任务、文章审核”随意打散。

品牌库是所有资料和任务的根节点。关键词、蒸馏词、知识库、图库、生成任务、审核和文章库都必须显示当前品牌归属。

## 3. 页面气质

整体参考 Codex / ChatGPT 工作台质感：

- 左侧窄导航。
- 中间主工作区。
- 右侧上下文质检面板，只显示当前步骤相关状态和下一步。
- 背景克制。
- 留白充足。
- 按钮少而明确。
- 字段分组清晰。
- 信息层级清楚。

避免：

- 传统后台密集表格。
- 大量鲜艳按钮。
- 乱堆数据卡片。
- 说明文字过多。
- 一屏出现太多操作入口。
- 操作区和结果区割裂。
- 右侧放和当前动作无关的拼凑信息。
- 顶部按钮和下方内容没有关系。

## 3.1 页面操作结构

每个实操页面统一采用同一种成熟 SaaS 操作结构：

```text
页面标题 + 当前品牌
主操作条：本页最重要的1-2个按钮
内容列表：展示当前品牌已有数据
当前操作区：新增、导入、编辑或创建任务
右侧状态区：资料完整度、规则命中、下一步
```

不使用“左边列表、右边随便解释”的割裂布局。右侧内容必须回答三个问题：

- 当前品牌这一步准备好了吗。
- 缺什么会影响生成。
- 下一步该点哪里。

## 4. 工作台

工作台不做纯数据大屏，而是生产状态页。

必须显示：

- 今日生成文章。
- 审核通过率。
- 平均豆包模拟分。
- 待重写文章。
- 已入库文章。
- 待分发文章。
- 项目资料完整度。
- 最近失败原因。

主视觉应是流程状态：

```text
资料准备 -> 问题规划 -> 标题生成 -> 单篇写作 -> 审核评分 -> 入库分发
```

## 5. 项目资料页

项目资料页要围绕 1.0 输入设计。

核心区块：

- 基础信息：项目名称、推荐名称、行业、城市、核心词。
- 关键词库：粘贴、导入、去重、预览。
- 品牌资产：上传 Word/TXT/Markdown 或粘贴文本。
- 权威引证：上传 Word/TXT/Markdown 或粘贴文本。
- 品牌图库：上传图片、打标签、选择可用场景。
- 禁用规则：默认规则已启用，自定义补充。

资料完整度要可见，但不要阻止用户生成测试篇。资料严重缺失时，不允许批量正式生成。

1.0 实际页面中，项目资料拆到品牌库、关键词、品牌知识库和品牌图库四个页面完成，但它们必须共享同一个当前品牌上下文。

## 6. 蒸馏词页

蒸馏词页承接成熟系统中的问题拓展能力。

核心功能：

- 从核心词和关键词库生成用户问题。
- 支持哪家好、推荐、怎么选、靠谱吗、测评、口碑、避坑、验收等推荐型问题。
- 每个问题可绑定文章方向。
- 每个问题可查看是否已生成文章。
- 每个问题可查看收录状态或待查询状态。
- 系统必须做问题去重，避免同一主词下反复生成同一种问题。
- 费用、多久、是什么、教程类问题只能作为正文补充或FAQ，不进入主写作任务池。

标题不是一级模块。写作任务在同一次文章生成中完成标题和正文，不拆成标题API和正文API。

## 7. 写作任务页

写作任务页要像任务队列，而不是表格后台。

创建任务时用户只选择：

- 项目。
- 核心词。
- 蒸馏疑问词来源。
- 生成篇数。
- 文章方向范围。
- 是否调用图库。
- 审核分数线，默认90。

标题提示词、文章提示词、新闻风格、豆包高分规则默认启用，不作为普通用户每次必须配置的复杂选项。高级用户可以在系统设置里维护默认规则。

系统自动调用文章生成指令，在同一单篇任务里生成标题、文章计划卡和正文。多个API只用于并发处理多篇单篇任务，不能拆开同一篇的标题和正文。

每张计划卡显示：

- 用户问题。
- 拟定标题。
- 文章方向。
- 选用关键词。
- 推荐企业切入方式。
- 预计图片位置。
- 状态。
- 审核分。

## 8. 文章审核页

右侧质检面板必须持续存在。

质检项：

- 核心词是否出现。
- 关键词库是否自然使用。
- 标题是否问题化。
- 新闻口吻是否达标。
- 是否像说明文。
- 推荐企业是否自然成为答案样本。
- 品牌资产是否准确。
- 权威引证是否合理。
- 是否有FAQ。
- 是否有表格/清单。
- 是否有2张图片位。
- 是否有禁用词。
- 是否有旧项目污染。
- 豆包模拟分。

审核结果要给普通用户能看懂的原因，不要只给技术错误码。

审核页不负责继续写作，不展示无关项目数据。通过的文章进入成品文章库；失败的文章只退回当前篇重写。

## 9. 文章编辑页

推荐布局：

```text
左：文章目录/段落定位
中：正文编辑器
右：质检面板
```

编辑器要像文档：

- 标题。
- 来源/日期。
- 正文段落。
- 小标题。
- 表格。
- 图片位。
- FAQ。
- 参考资料。

不要像代码编辑器，也不要像普通富文本后台。

## 10. 分发中心

1.0 可以先做预留，但页面逻辑要提前留好。

分发目标：

- 官网。
- 新闻源。
- 博客园。
- 今日头条。
- 搜狐。
- 百家号。
- 自媒体账号。

分发前要允许生成平台版：

- 平台标题。
- 平台摘要。
- 图片选择。
- 参考资料保留方式。
- 发布状态。
- 发布链接。

## 11. 视觉验收

合格 UI：

- 像成熟 SaaS 工具。
- 用户不用懂提示词。
- 生产流程一眼能看懂。
- 文章质量状态始终可见。
- 失败原因清楚。
- 资料、词库、任务、审核、文章库之间关系明确。

不合格 UI：

- 像传统后台。
- 表格铺满全屏。
- 右侧没有质检。
- 文章生成入口不清楚。
- 项目资料和关键词逻辑混乱。
- 看不出这是 GEO 内容生产系统。
