# 当前系统模块对照老系统复盘

复盘时间：2026-09-01

本轮不生成文章，只检查规则、模块目标、UI操作、数据链路和按钮闭环。结论：左侧大栏目方向已经接近，但右侧实操页还没有完全达到“老系统简约操作 + 新系统品牌资料增强”的标准。后续应先修工作流和数据归属，再跑文章生成。

## 1. 总体判断

当前系统已经具备这些正确方向：

- 左侧一级导航已经按生产链路组织：企业品牌库、品牌资料库、品牌文章系统、品牌媒体投喂。
- 核心词和关键词库已经拆开，不再把关键词库放在核心词页。
- 生成任务页已改为从已有品牌、核心词、蒸馏词、关键词库、知识库、图库中选择。
- 文章审核和成品文章库已经分开，成品库支持任务列表、文章列表、全文查看和下载。
- 服务端提示词已经有标题提示词、正文提示词、七层提示词栈和审核红线。

但仍有必须修的结构问题：

- 多处仍有硬编码演示数据，清空后可能回弹旧项目。
- 蒸馏词没有品牌字段，只按核心词关联，多个品牌使用同一核心词时会串库。
- 关键词库弹窗仍有部分文案容易让用户理解成“候选词复杂管理”，应继续简化为一个拓展词库框。
- 品牌图库目前保存的是图片数量和文件名状态，不是真实可复用图片资产。
- 写作指令不再作为独立页面，默认提示词由系统内置执行，普通用户不需要手动选择。
- 首页仍偏展示型，和老系统的操作入口相比略重。

## 2. 企业品牌库

目标：添加品牌项目，作为全部数据根节点。

当前状态：

- 可以添加品牌。
- 添加品牌时会同步创建核心词和蒸馏词。
- 删除品牌时有级联删除逻辑。

问题：

- 默认项目数组仍写在代码里，空状态时可能出现曝光率、长松、静源等旧数据。
- 添加字段里“生成目标、最低入库分”不应作为品牌基础字段出现，1.0 可以隐藏到系统设置。

修正方向：

- 所有业务默认数据改为空。
- 品牌库只保留品牌项目名、品牌名称、推荐词、核心词、行业、城市。
- 删除品牌必须同步删除该品牌全部关联数据。

## 3. 核心词 / 蒸馏词

目标：添加核心词，自动生成推荐型蒸馏词。

当前状态：

- 页面分为核心词列表和蒸馏词列表。
- 添加核心词后能生成“哪家靠谱、怎么选、推荐哪家”等问题。
- 删除核心词会删除对应蒸馏词和关键词库。

问题：

- 蒸馏词数据结构只保存：核心词、疑问词、状态、时间；没有品牌字段。
- 如果两个品牌都使用“西安GEO公司”，蒸馏词会混在一起。
- 添加核心词弹窗里的“归属品牌”是文本输入，不应手动改，应选择当前品牌或只读。

修正方向：

- 蒸馏词结构改为：品牌、核心词、蒸馏疑问词、收录状态、创建时间。
- 蒸馏词查询必须同时匹配品牌和核心词。
- 添加核心词弹窗里品牌只读或下拉选择，不允许乱填。

## 4. 关键词库

目标：按品牌和核心词拓展行业、场景、区域、平台辅助词。

当前状态：

- 页面已拆成关键词库。
- 有品牌选择、核心词选择、拓展关键词按钮。
- 弹窗已有项目名称、推荐词、核心词、行业/场景词、区域词、拓展词库。
- 列表支持筛选、优先、删除。

问题：

- 生成候选逻辑仍包含本地模拟，正式接入时必须明确“5118真实返回”或“本地模拟”。
- 弹窗说明要更像老系统：生成词直接进入拓展词库框，用户编辑后保存，不要额外候选列表。
- “优先”按钮可以保留，但要表达为写作优先调用，不是强制堆词。

修正方向：

- 保留两个按钮：生成拓展词、保存到关键词库。
- 不增加复杂候选区。
- 接 5118 后，把返回词写入拓展词库框，再让用户筛选保存。

## 5. 品牌知识库

目标：按品牌保存品牌资产和权威引证。

当前状态：

- 可以添加资料。
- 已区分品牌资产和权威引证。
- 列表支持编辑、删除。

问题：

- 知识库内容只是文本保存，还没有文件导入解析闭环。
- 完整度靠字符数粗略计算，可以先保留，但不能误导为真实质量评分。

修正方向：

- 1.0 保持直接粘贴/导入文本。
- 明确品牌资产和权威引证是内部写作依据，正文不得出现内部标签。

## 6. 品牌图库

目标：上传当前品牌图片，供文章正文中段调用。

当前状态：

- 已有添加图片弹窗。
- 已有本地上传入口。
- 列表支持编辑、上传、删除。

问题：

- 当前只记录选择了几张图片，没有真实保存图片文件、预览图和可调用路径。
- 生成文章时只是用“图片位数量”，没有真正绑定某张图。

修正方向：

- 1.0 至少要把图片保存到本地/服务器目录，记录图片名称、URL/path、分类、用途、品牌。
- 生成任务选择图库时，应能带出可调用图片列表。

## 7. 生成任务

目标：从当前品牌资料包创建任务，让系统按单篇队列生成文章。

当前状态：

- 创建任务弹窗已从已有品牌、核心词、蒸馏词、关键词库、知识库、图库中选择。
- 任务列表有开始、查看结果、删除。
- 后台任务走 `/api/jobs/start`。

问题：

- `draft` 内部还保留 `contentPrompt: 随机生成文章`、`titlePrompt: 不重写标题`，虽然界面没显示，但语义不符合当前规则。
- 文章分类/批次如果为空会出现默认批次，最好自动创建当前品牌默认批次或隐藏批次。
- 删除任务只删任务行，未明确同步删除该任务下未入库文章。

修正方向：

- 任务弹窗只保留选择已有资料和生成篇数。
- 默认提示词不出现在任务表单，只显示“默认写作规则已启用”。
- 删除任务时同步清理该任务未入库文章；已入库文章单独确认。

## 8. 默认标题提示词 / 正文提示词

目标：作为系统配置，不作为普通用户每次生成时的操作项。

当前状态：

- 标题提示词、正文提示词、提示词栈、单篇新闻生成器、审核只做拦截已经进入系统默认规则，不再作为普通用户页面。
- 服务端实际也有 `buildTitlePrompt`、`buildSingleBodyPrompt` 等逻辑。

问题：

- “写作指令”页面已从主流程移除，默认提示词只作为系统能力存在。
- 标题提示词和正文提示词在 UI 上没有清楚说明“默认启用，不需要选择”。

修正方向：

- 写作规则只在系统设置展示默认约束，不做普通用户必填入口。
- 生成任务页只显示默认规则状态，不让用户选择复杂提示词。
- 标题和正文仍在服务端分开生成，但同一篇文章共享同一个任务数据包。

## 9. 文章审核

目标：查看完整正文、评分项、失败原因，通过后入库。

当前状态：

- 支持全部、待审核、失败列表、通过列表筛选。
- 支持审核详情、完整正文、退回、通过入库。
- 低于90分会退回。

问题：

- 审核项能看，但对“品牌资产调用”和“权威引证调用”的展示还偏弱。
- 如果是 API 未达标，需要清楚显示“API原文未达标”，不要让用户误以为系统已经补好了。

修正方向：

- 审核详情增加调用数据摘要：核心词、推荐词、关键词库、品牌资产、权威引证、图库。
- 失败原因保留系统原始判定，不做聊天补救。

## 10. 成品文章库

目标：管理通过审核的文章，支持按任务查看、全文查看、下载和分发。

当前状态：

- 已有任务列表和当前任务文章列表。
- 支持全文查看、下载本文、下载全部、下载本批。

问题：

- 如果当前任务没有通过文章，列表为空时需要有明确空状态。
- 下载依赖 `/api/articles/export`，失败时有浏览器备用下载；这属于可接受的下载降级，但要保证正式环境服务端导出稳定。

修正方向：

- 保留“任务列表 + 当前任务文章列表”结构。
- 默认只显示最近一次任务或用户选中的任务。
- 下载入口只针对当前任务，避免混入旧文章。

## 11. 品牌媒体投喂

目标：从成品文章库选择文章，再发布到官网、新闻源或其他平台。

当前状态：

- 目前仍偏展示，投喂接口可以后置。

修正方向：

- 先不影响文章生成主链路。
- 1.0 只保留待配置和创建分发任务入口。

## 12. 优先整改清单

第一优先级：

- 清除所有硬编码演示业务数据，避免清空后回弹。
- 蒸馏词加品牌字段，彻底防止跨品牌串库。
- 任务删除同步清理该任务未入库文章。
- 图库上传保存真实文件或可调用路径。

第二优先级：

- 品牌库添加字段精简。
- 写作指令从主流程移除，批次由生成任务自然形成。
- 生成任务页增加本次调用资料包摘要，但不要变复杂。
- 审核详情增加资料调用摘要。

第三优先级：

- 首页减少展示型卡片，回归老系统的快速入口和数据概览。
- AI诊断和数据中心放到底部工具区，不干扰生产流程。

## 13. 下一步执行标准

下一轮改系统时，不再新增花哨模块，只修闭环：

```text
空数据启动
-> 添加品牌
-> 自动生成核心词和蒸馏词
-> 拓展关键词库
-> 添加品牌资产与权威引证
-> 上传图库并保存路径
-> 创建生成任务
-> 查看任务进度
-> 审核完整正文
-> 入库
-> 全文查看
-> 下载
```

这条链路跑通前，不做批量生成、不做投喂、不做新模块。
