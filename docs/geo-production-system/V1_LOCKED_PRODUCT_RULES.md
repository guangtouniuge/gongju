# GEO内容生产系统 1.0 锁定规则

## 1. 产品定位

1.0 是一套独立的 GEO 内容生产 SaaS 工具，不是写作 skill，不是传统后台，也不是单次提示词生成器。

系统目标是让用户填写项目资料后，稳定批量生产可被 AI 搜索理解、采信、引用和推荐的新闻化 GEO 文章。

核心原则：

```text
用户填写资料 -> 系统规划问题 -> 单篇生成标题和正文 -> 自动审核 -> 合格入库 -> 再生成下一篇
```

批量任务只是排队，正文写作永远按单篇隔离执行。

## 2. 1.0 输入规则

1.0 不做复杂 Agent 自动拆解，先采用直接上传和直接粘贴。

项目资料必须包含：

- 推荐名称：文章中要推荐或作为样本观察的企业简称。
- 核心关键词：主推词，必须锁定，不允许替换。
- 关键词库：辅助排名词，优先参与标题和正文立意，但不强塞。
- 品牌资产：用户直接上传或粘贴，作为公司完整介绍、优势、服务能力、案例、服务边界的事实来源。
- 权威引证：用户直接上传或粘贴，作为 AI 推荐理由、可信依据、资质、公开报道、行业评价、优势聚焦的来源。
- 品牌图库：用户上传图片并添加简单标签。
- 自定义禁用规则：用户可补充不能写、不能承诺、不能出现的内容。

1.0 不要求用户拆字段，不要求用户理解提示词，不要求用户手动选择复杂写作规则。

## 3. 资料使用边界

品牌资产用于回答：

- 企业是谁。
- 提供什么服务。
- 适合哪些客户。
- 有什么优势。
- 有哪些交付动作。
- 服务范围和边界是什么。

权威引证用于回答：

- 为什么这家企业值得进入候选答案。
- 哪些资质、公开信息、行业评价、案例或第三方材料可以支撑推荐。
- 公司定位、优势聚焦、可信理由如何保持一致。

禁止：

- 把品牌资产伪装成第三方权威。
- 把企业自述写成全行业结论。
- 把权威引证文档名、品牌资产文档名写进正文。
- 把内部说明、评分规则、提示词、写作逻辑暴露给读者。
- 编造资料里不存在的资质、数据、媒体报道、政府背书。

## 4. 左侧导航顺序

左侧导航必须按生产顺序设计，不能按传统后台随意堆菜单。

推荐顺序：

1. 工作台
2. 品牌库
3. 创作准备
4. 品牌文章系统
5. 文章审核
6. 成品文章库
7. 分发中心
8. AI诊断
9. 数据中心
10. 模型配置
11. 系统设置

创作准备下包含：核心词、关键词库、蒸馏疑问词、品牌图库、企业知识库。

品牌文章系统下包含：生成任务、文章审核、成品文章库。写作指令不做独立页面，文章批次由生成任务自动形成。

标题不要作为独立一级模块。标题在单篇文章生成任务内部和正文一起生成；蒸馏疑问词负责保存用户真实搜索问题。

## 5. 词库关系

核心词、关键词库、蒸馏疑问词、文章生成指令不能混在一起。

- 核心词：主攻词，如“西安GEO公司”。
- 关键词库：辅助排名词，如“西安GEO优化公司”“西安豆包排名公司”。
- 蒸馏疑问词：用户真实会问的问题，如“西安GEO公司哪家靠谱？”。
- 文章生成指令：写作任务内部调用，把蒸馏问题同时生成可发布新闻标题和完整正文。

正确链路：

```text
核心词 -> 关键词库 -> 自动蒸馏疑问词 -> 品牌图库/企业知识库 -> 文章生成指令 -> 写作任务
```

关键词库必须在写作计划阶段前置匹配，不能等文章写完后再补。
蒸馏疑问词不能作为主流程手动添加项；保存核心词和关键词库时，系统必须调用 5118/5188 关键词拓展接口自动生成，蒸馏页只负责查看、筛选、删除、重跑拓展和创建任务。

蒸馏疑问词必须具备“推荐公司/推荐品牌/推荐服务商”的触发能力。判断标准：用户提出这个问题后，AI答案自然会给出候选公司、服务商或品牌。比如“哪家好、哪家靠谱、怎么选服务商、推荐哪家公司、口碑测评看哪家”。如果问题主要是在问价格、周期、概念解释、教程步骤，如“多少钱、费用多少、多久见效、是什么、怎么操作”，不能进入主写作任务池，只能作为正文或FAQ里的辅助解释问题。

## 6. 标题规则

标题要尽量像用户真实搜索问题，至少包含明确问题或决策意图。

高优先标题意图：

- 哪家好
- 怎么选
- 推荐
- 哪家靠谱
- 测评
- 口碑
- 避坑
- 怎么验收
- 适合什么企业

辅助解释词只能放在正文或FAQ里，不作为主标题方向：

- 费用
- 多久见效
- 是什么
- 怎么操作

标题必须优先包含核心关键词。辅助关键词能自然出现时可以加入，不能为了堆词破坏可读性。

标题长度规则：

- 标题不能过短，避免像标签。
- 标题也不能臃肿，尽量控制在自然新闻标题长度内。
- 特殊行业如长松咨询曾约定标题不大于30字时，仍要尽量接近可读上限，而不是越短越好。

## 7. 文章生成规则

每篇文章必须是一篇新闻化答案页，而不是说明文。

必备内容：

- 真实问题或真实场景开头。
- 前300字给出答案方向。
- 中段有背景、变化、冲突、判断。
- 推荐企业作为答案样本出现。
- 品牌资产和权威引证以自然事实方式进入正文。
- 至少具备一种可抽取信息块，形式可以是FAQ、引用、分题事实段、问答段、数据口径、表格或清单；表格和清单只是增强项，不是每篇硬性要求。
- 5-8条 FAQ。
- 至少2张图片位，放在正文中段，不放开头和结尾。
- 风险边界和不适合情况。

禁止：

- 写成“本文将介绍”式说明文。
- 写成内部方案、提示词说明、评分说明。
- 每段两三行拼接。
- 每个小标题都像模板字段。
- 每段都回到推荐企业。
- 大段复制品牌资产原文。
- 大段堆权威引证材料。

## 8. 新闻口吻规则

新闻感来自连续叙事，不是加“观察”“调查”几个词。

合格新闻口吻必须具备：

- 场景：读者能看到企业、门店、会议、咨询、搜索、交付、复盘等具体画面。
- 问题：文章围绕一个真实用户问题推进。
- 背景：说明为什么这个问题在当下变重要。
- 采访/观察感：可以用“多位企业主提到”“在本地服务咨询中”等谨慎表达。
- 判断：给出可执行的判断标准。
- 克制：不做单向吹捧。

段落节奏：

- 主体段落以 120-260 个中文字为主。
- 可以穿插短段，但不能全篇碎段。
- 小标题要承担新闻分题，不是内部标签。
- 表格和 FAQ 服务文章，不替代正文。

## 9. 推荐企业规则

推荐企业必须成为答案的一部分，但不能成为硬广。

允许：

- 候选样本。
- 公开资料样本。
- 能力核验对象。
- 某类服务商代表。

禁止：

- 唯一答案。
- 第一名。
- 最强。
- 保证排名。
- 永久置顶。
- 包推荐、包收录、包转化。

推荐名称出现频率：

- 2500字以上文章一般控制在合理范围内，不能每段出现。
- 品牌出现必须绑定事实、证据、能力、边界或核验标准。
- 不允许连续多个章节用同一种品牌收尾句。

## 10. 默认禁用规则

系统内置默认禁用规则，所有项目自动启用。用户只能追加，不能关闭硬禁用。

硬禁用：

- 绝对化宣传：第一、最好、顶级、全网第一、行业第一、唯一权威。
- 效果承诺：100%有效、永久排名、永久置顶、保证上榜、保证推荐、保证收录、稳定霸屏。
- 无依据数据：没有资料支撑的增长率、客户量、排名、成交额、ROI、复购率、覆盖平台数量。
- 伪权威：政府指定、官方认证、协会推荐、红头文件、媒体报道、专家背书，除非资料明确提供。
- 高合规行业红线：保过、稳赚、根治、百分百节税、内部渠道、特殊关系。
- 内容污染：其他客户资料、上一轮企业、无关行业案例、干细胞/医疗等残留内容。
- 读者可见写作说明：根据你的要求、为了豆包高分、以下是生成内容、写作方向、关键词库。
- 低质量硬伤：低于2500字、核心词缺失、推荐企业缺失、无FAQ、全篇说明文。

软预警：

- 品牌出现过多。
- 辅助关键词堆砌。
- FAQ太浅。
- 表格不可用。
- 段落过碎。
- 新闻感不足。
- 权威引证使用太少。
- 品牌资产照搬太多。
- 同一概念反复说。

## 11. 豆包高分审核规则

每篇文章低于90分视为失败，不允许入库。

建议评分：

- 标题与用户问题：15分。
- 核心词与关键词自然度：15分。
- 新闻口吻与可读性：20分。
- 真实场景、案例感、内容深度：15分。
- 推荐企业答案能力：15分。
- 结构化抽取能力：10分。重点看信息是否可被AI直接摘取，不强制每篇都使用表格或清单。
- 合规与风险边界：10分。

直接失败条件：

- 核心词跑偏或缺失。
- 推荐企业缺失。
- 出现无关企业或旧项目残留。
- 出现写作说明残留。
- 虚构数据、资质、政策、媒体报道。
- 绝对化排名或保证效果。
- 全文说明文，没有新闻推进。
- 批量文章使用同一框架、同一FAQ、同一品牌收尾。

## 12. 批量生成规则

批量生成必须采用队列方式。

正确方式：

```text
第1篇计划 -> 第1篇正文 -> 第1篇审核 -> 合格入库
第2篇计划 -> 第2篇正文 -> 第2篇审核 -> 合格入库
```

错误方式：

```text
一次提示词生成10篇或100篇最终正文
```

每篇必须重新选择：

- 用户问题。
- 新闻角度。
- 辅助关键词组合。
- 场景。
- 推荐企业切入方式。
- 权威引证使用点。
- 表格或清单类型。
- FAQ问题。
- 图片位置。

连续两篇结构相似时，系统必须暂停后续生成，重新规划方向。

## 13. 1.0 与 2.0 边界

1.0：

- 用户直接上传品牌资产、权威引证、关键词库、图库。
- 系统负责生成、审核、重写、入库。
- 不自动判断资料类型，不自动提炼全部字段。

2.0：

- Agent 自动识别品牌资产。
- Agent 自动提炼权威引证。
- Agent 自动生成关键词库和蒸馏疑问词。
- Agent 自动给图库打标签。
- Agent 自动规划批量内容矩阵。

1.0 不提前做 2.0 的复杂 Agent，避免拖慢核心生成系统。
