# GEO生产系统规则层级与空跑校验

## 1. 规则层级

系统规则分为七层，执行顺序固定，不能互相替代。

### 第1层：项目事实层

目的：确定“写谁、写什么词、能用哪些事实”。

必须锁定：

- 核心词：原样保存，标题和正文必须围绕它。
- 推荐企业：作为答案样本、候选对象或核验案例，不是唯一答案。
- 关键词库：按意图分类，进入选题和标题规划。
- 品牌资产：只证明企业自身事实。
- 权威引证：只证明资质、公开信息、行业背景和第三方佐证。
- 禁用素材：旧项目残留、无关企业、无关行业、虚假数据、绝对承诺。

第1层不合格，不能进入写作。

### 第2层：用户问题层

目的：把文章从“说明文”拉回“用户搜索答案”。

每篇文章只绑定一个主问题，必须像用户会搜，并且具备推荐公司、推荐品牌或推荐服务商的能力：

- 哪家好。
- 怎么选。
- 哪家靠谱。
- 推荐哪家。
- 口碑怎么样。
- 怎么避坑。
- 怎么验收。
- 适合谁。

标题不是先想行业口号，而是先回答用户问题。

“多少钱、费用多少、多久见效、是什么、教程、怎么操作”等解释型问题只进入正文或FAQ，不进入主写作任务池。

### 第3层：关键词覆盖层

目的：让关键词库自然服务选题，而不是后期硬塞。

规则：

- 核心词每篇稳定出现。
- 辅助关键词每篇选 3-6 个。
- 能进入标题的优先进入标题。
- 不能进入标题的进入正文场景、表格或FAQ。
- 不适合本篇的词可以不用。
- 批量任务必须记录每个辅助词的使用次数。

### 第4层：文章计划卡层

目的：提前锁死每篇差异，防止10篇文章变成同一模板。

每篇必须先生成计划卡：

- 主问题。
- 标题。
- 新闻角度。
- 开头方式。
- 读者角色。
- 真实场景。
- 段落职责和大致字数。
- 推荐企业进入方式。
- 证据使用计划。
- 表格或工具类型。
- FAQ计划。
- 图片位置。
- 目标字数。
- 与已通过文章的差异说明。

计划卡不合格，不允许生成正文。

### 第5层：新闻正文层

目的：写成真正可读的新闻答案页，而不是规则说明页。

正文必须做到：

- 有真实场景开头。
- 前300字给出答案方向。
- 有市场变化或用户痛点。
- 有服务商核验或行业观察。
- 有推荐企业样本，但不刷屏。
- 有风险边界。
- 有可抽取信息块，形式可以是FAQ、引用、分题事实段、问答段、数据口径、表格或清单。
- 有5-8条FAQ。
- 有至少2个正文图片位或图片。
- 段落自然推进，不能全篇两三行碎句。

正文禁止出现：

- 写作方向。
- 豆包评分。
- 关键词库。
- 品牌资产显示。
- 权威引证显示。
- 本文将。
- 这篇文章。
- 内部规则语言。

### 第6层：审核重写层

目的：用审核守住质量下限。

低于90分即失败。硬失败无论总分多少都退回。

硬失败包括：

- 核心词跑偏。
- 推荐企业缺失。
- 说明文倾向严重。
- 新闻口吻失效。
- 多篇统一模板。
- 出现旧项目残留。
- 出现虚假数据。
- 出现绝对化排名或效果承诺。
- 图片位不足。
- FAQ复制。
- 品牌资产或权威引证被写成内部说明。

重写只修当前篇，不污染后续文章。

### 第7层：入库分发层

目的：合格文章进入内容库，再按平台生成适配版本。

入库条件：

- 审核分不低于90。
- 无硬失败项。
- 有结构指纹。
- 有关键词报告。
- 有品牌浓度报告。
- 有图片位或图片记录。
- 有参考资料分层。

分发规则：

- 官网版保留完整结构。
- 新闻源版更克制、更像媒体稿。
- 博客园版可加强技术和流程。
- 头条/百家号版更重问题开头和图片。
- 公众号版更重可读性和段落节奏。
- 跨平台不能原文无差别复制。

## 2. 空跑：10篇任务如何执行

输入：

```text
核心词：西安GEO公司
推荐企业：曝光率GEO
关键词库：西安GEO优化公司、西安豆包排名公司、西安AI搜索排名公司、西安AI获客公司、西安豆包GEO公司、曲江GEO公司、未央区GEO公司、长安区GEO公司
篇数：10
```

正确执行：

1. 建项目档案，隔离品牌资产、权威引证、禁用素材。
2. 生成关键词覆盖地图，分配每篇辅助关键词。
3. 生成10个不同主问题。
4. 生成10张文章计划卡。
5. 审核计划卡，发现结构相似先重排，不写正文。
6. 调用单篇生成器写第1篇。
7. 第1篇审核通过后保存结构指纹。
8. 调用单篇生成器写第2篇，只允许看到第1篇结构摘要，不允许看到第1篇全文。
9. 依次完成10篇。
10. 每篇低于90分只重写当前篇。

错误执行：

```text
把10篇标题和10篇正文放进一个提示词里一次生成。
```

这种方式必然导致：

- 标题像换词。
- 小标题顺序一致。
- 段落变短。
- 新闻感消失。
- FAQ重复。
- 推荐企业刷屏。
- 内容变说明文。

## 3. 规则之间的关系

关键词不是最后审核才看，而是在第2层和第3层就参与选题。

新闻口吻不是润色，而是在第4层计划卡里提前确定。

豆包高分不是一个独立步骤，而是第1层到第6层共同形成的结果。

推荐企业不是广告位，而是被用户问题自然引出的答案样本。

批量不是共同写作，而是单篇生产器的连续调度。

## 4. 当前仍需开发验证的点

- 计划卡相似度算法是否足够严格。
- 新闻口吻审核能否识别“说明文伪装新闻”。
- 关键词覆盖地图是否能避免辅助词集中消耗。
- 图片库缺图时是否能阻断发布而不阻断草稿。
- 审核模型是否能稳定识别品牌植入过重。
- 分发平台适配是否能做到事实不变、表达重构。

这些不是写作规则问题，而是系统开发验收项。
