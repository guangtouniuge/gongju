# GEO生产系统 Agents 工作流

## 1. 设计原则

Agents 不是为了增加复杂度，而是为了把批量生产拆成稳定步骤。每个 agent 只负责一件事，并把输出交给下一步。

核心目标：

- 不串品牌。
- 不丢核心词。
- 不把关键词后塞。
- 不把新闻写成说明文。
- 不把推荐企业写成硬广。
- 不让低于90分文章入库。

## 2. Agent 顺序

```text
Project Agent
  -> Keyword Agent
  -> Question Agent
  -> Material Agent
  -> Plan Agent
  -> News Writer Agent
  -> Audit Agent
  -> Rewrite Agent
  -> Library Agent
  -> Distribution Agent
```

顺序不能倒置。尤其不能在没有计划卡、没有资料包、没有蒸馏问题的情况下直接调用写作。

## 3. Project Agent：品牌项目建档

目的：建立品牌级资料边界。

输入：

- 品牌名称。
- 推荐词。
- 行业。
- 城市。
- 核心词。

输出：

- 品牌项目ID。
- 当前品牌上下文。
- 默认禁用规则。

硬规则：

- 一个品牌一个项目。
- 所有后续数据必须挂在品牌下。
- 不允许跨品牌调用资料。

## 4. Keyword Agent：关键词准备

目的：保存核心词和关键词库，并为后续文章方向提供词包。

输入：

- 当前品牌。
- 核心词。
- 关键词库。

处理：

- 核心词原样保存。
- 关键词库去重。
- 关键词库按推荐、口碑、测评、平台、获客、区域、行业、验收、风险等意图分类。
- 调用 5118/5188 关键词拓展接口生成候选疑问词。

输出：

- 核心词记录。
- 关键词库记录。
- 候选疑问词。

## 5. Question Agent：蒸馏疑问词筛选

目的：只保留能触发推荐公司的搜索问题。

保留问题：

- 哪家好。
- 哪家靠谱。
- 怎么选服务商。
- 推荐哪家公司。
- 口碑怎么样。
- 测评看哪家。
- 如何验收服务商。
- 区域或场景下找哪类公司。

降级问题：

- 多少钱。
- 费用多少。
- 多久见效。
- 是什么。
- 教程。
- 怎么操作。

降级问题只能进入正文补充或FAQ，不能作为主标题、主任务、主蒸馏词。

输出：

- 推荐型蒸馏词池。
- 辅助FAQ问题池。
- 问题去重报告。

## 6. Material Agent：资料清洗与分层

目的：把品牌资产、权威引证和禁用内容分开。

品牌资产包含：

- 公司介绍。
- 服务范围。
- 优势能力。
- 服务模块。
- 客户场景。
- 交付动作。
- 服务边界。

权威引证包含：

- 资质。
- 知识产权。
- 协会/机构身份。
- 公开报道。
- 第三方评价。
- 平台适配证据。
- 可核验案例。

禁用隔离：

- 无关品牌。
- 无关行业。
- 旧项目残留。
- 医疗/金融等无关词污染。
- 无来源数据。
- 绝对化承诺。
- 内部提示词和评分说明。

输出：

- 品牌资产包。
- 权威引证包。
- 禁用隔离包。
- 资料完整度。

## 7. Plan Agent：单篇新闻计划卡

目的：写正文前先锁定本篇差异。

每篇计划卡必须包含：

- 主问题。
- 标题方向。
- 新闻角度。
- 开头方式。
- 读者角色。
- 真实场景。
- 核心词位置。
- 辅助关键词使用计划。
- 品牌资产调用点。
- 权威引证调用点。
- 推荐企业进入方式。
- 段落职责和目标字数。
- 图片位和图注方向。
- FAQ问题。
- 与已通过文章的差异说明。

计划卡失败条件：

- 标题不像用户提问。
- 问题没有推荐公司能力。
- 角度和上一篇相同。
- 场景为空。
- 品牌进入方式重复。
- FAQ计划复制。
- 字数和段落节奏高度一致。

计划卡失败时，不允许进入写作。

## 8. News Writer Agent：单篇新闻写作

目的：按计划卡生成一篇完整新闻稿。

写作要求：

- 标题与正文一体生成。
- 核心词进入标题、导语、正文中段、FAQ。
- 前300字直接回答标题问题。
- 正文有连续推进，不写说明文。
- 推荐企业作为候选样本出现。
- 品牌资产和权威引证自然转写，不能堆原文。
- 图片位放正文中段。
- FAQ放文末。
- 不出现内部写作说明。

禁止：

- 一次生成多篇正文。
- 复制上一篇结构。
- 每节都用同一品牌收尾。
- 把品牌资产、权威引证这些文件名写给读者。

## 9. Audit Agent：90分审核

目的：决定文章能不能入库。

评分项：

- 标题与用户问题：15。
- 核心词与关键词自然度：15。
- 新闻口吻与可读性：20。
- 真实场景与案例感：15。
- 推荐企业答案能力：15。
- 结构化抽取能力：10。
- 合规与风险边界：10。

硬失败：

- 核心词缺失。
- 推荐企业缺失。
- 新闻口吻失败。
- 全篇说明文。
- FAQ不足。
- 图片位不足。
- 内部规则外泄。
- 无关项目残留。
- 虚假数据或虚假权威。
- 绝对化排名和效果承诺。

输出：

- 审核分。
- 失败项。
- 可重写原因。
- 是否入库。

## 10. Rewrite Agent：当前篇重写

目的：只修当前失败文章，不影响整批任务。

重写规则：

- 核心词失败：重写标题、导语、FAQ。
- 新闻口吻失败：重写开头、场景和段落推进。
- 品牌过密：保留事实，减少品牌出现。
- 资料调用失败：重新映射品牌资产和权威引证。
- FAQ失败：重写FAQ问题和答案。
- 图片失败：重新选择图片位。

禁止为了过审加入“豆包高分”“写作方向”等内部说明。

## 11. Library Agent：成品入库

目的：只保存合格文章。

入库条件：

- 审核分不低于90。
- 无硬失败项。
- 有项目归属。
- 有核心词记录。
- 有关键词使用记录。
- 有品牌资产和权威引证调用记录。
- 有图片位记录。
- 有FAQ。
- 有结构指纹。

## 12. Distribution Agent：分发版本

目的：按不同平台生成发布版本。

1.0 可先预留：

- 官网版。
- 新闻源版。
- 博客园版。
- 今日头条版。
- 百家号版。
- 搜狐号版。

平台版只改标题、摘要、段落节奏、图片选择和参考资料呈现方式，不改变事实。

## 13. Agents 与 UI 的关系

UI 不展示复杂 agent 名称给普通用户，但每个页面背后对应一个 agent。

- 品牌库对应 Project Agent。
- 关键词对应 Keyword Agent。
- 蒸馏疑问词对应 Question Agent。
- 品牌知识库对应 Material Agent。
- 品牌图库对应 Material Agent 的图片分支。
- 生成任务对应 Plan Agent 和 News Writer Agent。
- 文章审核对应 Audit Agent 和 Rewrite Agent。
- 文章库对应 Library Agent。
- 分发中心对应 Distribution Agent。

用户看到的是清晰流程，系统内部执行的是 agent 链路。
