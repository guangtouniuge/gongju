# GEO生产系统虚拟跑流程与遗漏审查

## 1. 虚拟测试场景

模拟项目：

```text
核心词：西安GEO公司
推荐企业：曝光率GEO
关键词库：西安GEO优化公司、西安豆包排名公司、西安AI搜索排名公司、西安AI获客公司、西安豆包GEO公司、曲江GEO公司、未央区GEO公司、长安区GEO公司
生成目标：10篇新闻文章
输出：Word + HTML预览
后续目标：推送官网草稿、新闻源分发
图片：每篇2张
最低审核分：90
```

## 2. 虚拟跑完整链路

### 2.1 项目创建

流程能跑通：

- 核心词可录入。
- 推荐企业可录入。
- 关键词库可录入。
- 品牌资产和权威引证可上传。

发现遗漏：

- 还没有定义“项目所属用户/团队”。
- 还没有定义“客户项目”和“自营项目”的区别。
- 还没有定义项目归档、复制、暂停、删除。
- 还没有定义同一个客户多个品牌如何隔离。

需要补充：

- 用户、团队、项目三层权限。
- 项目状态：draft、active、paused、archived。
- 项目复制功能，用于复用同类行业配置。

### 2.2 素材清洗

流程能跑通：

- 能区分品牌资产、权威引证、关键词、图片。
- 能隔离无关内容。

发现遗漏：

- 图片版权和来源没有规则。
- 用户上传资料是否允许被复用到其他项目没有规则。
- 历史文章能否作为“风格样本”还是“内容素材”需要更强隔离。
- 没有定义资料版本更新后，旧文章是否需要重新审核。

需要补充：

- 图片必须有来源字段：自有图库、授权图库、用户上传、生成图片。
- 用户资料默认只归当前项目使用。
- 参考文章只能学习结构，不进入正文素材。
- 品牌资料更新后，相关文章标记为 `needs_reaudit`。

### 2.3 用户问题与关键词计划

流程能跑通：

- 能先从用户问题出发。
- 能让关键词库前置参与标题和正文。

发现遗漏：

- 关键词没有“覆盖计划”，批量时可能前20篇用完热门词，后面重复。
- 没有定义关键词优先级消耗机制。
- 没有定义“同一关键词多少篇可重复使用”。
- 没有定义标题长度和可读性阈值。

需要补充：

- 批量任务先生成关键词覆盖地图。
- 每个辅助词记录使用次数。
- 同一辅助关键词连续出现不得超过2篇。
- 标题控制在“信息完整且不堆词”的范围，优先 18-32 个中文字，可按行业适当放宽。

### 2.4 新闻计划

流程能跑通：

- 有新闻角度池。
- 有真实场景要求。

发现遗漏：

- 新闻角度池还只是文字列表，没有“结构差异模板”。
- 没有定义不同新闻类型的段落节奏。
- 没有定义每篇字数差异。
- 没有定义批量时如何避免“只是栏目换位置”。

需要补充：

- 每个新闻角度都要有独立结构卡。
- 结构卡包含：开头类型、段落密度、表格位置、品牌进入点、FAQ方式、结尾方式。
- 批量前先生成10/30/100张文章卡，不直接写正文。
- 每篇目标字数不同，但不得低于用户设定下限。

### 2.5 单篇生成

流程能跑通：

- 单篇生成器是核心。
- 先生成一篇、审核一篇、通过一篇。

发现遗漏：

- 没有明确 AI Provider 失败后的回退策略。
- 没有定义超时、限流、余额不足。
- 没有定义生成中断后如何恢复。
- 没有记录每次生成使用的模型、提示词版本和成本。

需要补充：

- AI Provider 状态表。
- 失败重试机制。
- Token 和成本记录。
- Prompt 版本记录。
- 每篇任务可从最后状态恢复。

### 2.6 审核

流程能跑通：

- 低于90分重写。
- 硬失败项明确。

发现遗漏：

- 审核器如果误判，缺少人工复核入口。
- 没有定义“自动通过”和“建议人工看一眼”的灰区。
- 没有定义审核模型和生成模型是否分开。
- 没有定义最终人工确认后是否允许低于90分入库。

需要补充：

- 分数 >=90 自动通过。
- 85-89 进入人工复核。
- <85 自动重写。
- 硬失败无论分数多少都退回。
- 审核模型可与生成模型分开配置。

### 2.7 图片

流程能跑通：

- 每篇至少2张图。
- 图片中段插入。

发现遗漏：

- 图片库没有标签体系。
- 没有定义封面图和正文图的区别。
- 没有定义不同分发平台图片比例。
- 没有定义图片缺失时是用占位还是阻断发布。

需要补充：

- 图片字段：行业、场景、城市、人物、版权、比例、适用平台。
- 封面图可选，正文图必需。
- 官网/公众号/头条/新闻源可有不同图片比例。
- 缺图片时文章可生成，但发布状态不能变为 ready_to_publish。

### 2.8 导出与分发

流程能跑通：

- 可导出 Word、HTML、Markdown。
- 后续可推官网草稿。

发现遗漏：

- 不同平台版本规则不够细。
- 没有定义分发状态。
- 没有定义平台账号授权。
- 没有定义发布失败重试。
- 没有定义同一篇文章多平台分发时如何改写去重。

需要补充：

- PlatformAdapter 模块。
- 每个平台一套标题、摘要、图片、参考资料、正文长度规则。
- 分发状态：draft、scheduled、published、failed、needs_edit。
- 同一篇文章跨平台必须生成平台版，不直接复制原文。

### 2.9 官网对接

流程能跑通：

- `gongju.7chacha.com` 独立生产。
- `www.7chacha.com` 承接发布。

发现遗漏：

- 官网接口鉴权没有定义。
- 官网栏目字段没有完全规范。
- 草稿推送后如何回传 URL 没写细。
- 发布后 AI答案回看还没有数据结构。

需要补充：

- 官网 API Token。
- 官网栏目、标签、摘要、封面图字段。
- 推送后保存 draft_id、published_url。
- AI答案回看任务单独建表。

## 3. 最大风险点

### 风险1：批量生成又退化成统一模板

原因：

- 只定义了“角度不同”，但没有给每个角度定义结构卡。

解决：

- 批量生成前先生成 ArticlePlanCards。
- 每张卡锁定标题问题、新闻结构、段落节奏、表格类型、FAQ方式、品牌进入点。

### 风险2：UI变成普通后台

原因：

- 当前文档讲了流程，但还没写产品界面规则。

解决：

- 增加 UI/UX 产品规划文件。
- 明确 GPT式工作区、左侧项目、右侧质检、中央文章编辑器。

### 风险3：数据和图片违规

原因：

- 数据来源、图片版权、生成图片和授权图库还没建模。

解决：

- 数据、图片都必须保存来源、授权、用途。

### 风险4：成本不可控

原因：

- 批量生成会产生大量模型调用，目前缺少成本预算。

解决：

- 每个任务记录模型、Token、成本。
- 可设置项目预算和单篇重写上限。

### 风险5：分发端重复

原因：

- Word、官网、头条、博客园如果用同一篇原文，后续仍可能有重复风险。

解决：

- 分发中心必须生成平台版。
- 平台版保留事实，但标题、摘要、段落节奏、图片和结尾要适配。

## 4. 需要补齐的文件

已补齐：

- `UI_PRODUCT_PLAN.md`：可售卖 SaaS 界面规划。
- `ARTICLE_PLAN_CARD_SPEC.md`：文章计划卡规范，解决批量同质化。
- `PROVIDER_AND_COST_RULES.md`：AI接口、成本、重试、预算规则。
- `DISTRIBUTION_ADAPTER_RULES.md`：官网和第三方平台分发适配规则。

已回流到正式规则：

- `DATA_MODEL_AND_API.md` 已补充用户/团队、项目类型、素材版本、图片资产、文章计划卡、AI调用日志。
- `WORKFLOW_CONSTRAINTS.md` 已补充规则优先级、执行顺序、参考资料分层、批量稳定性。
- `IMPLEMENTATION_ACCEPTANCE_CHECKLIST.md` 已补充上线前单篇/三篇/十篇模拟验收。

仍需开发时验证：

- 计划卡审核能否真正拦截统一框架。
- 生成模型和审核模型分离后，低分重写是否稳定。
- 图片库缺失时，文章草稿与发布状态是否能正确分离。
- 官网和分发平台接口是否能回写URL和发布状态。

## 5. 结论

当前主链路已经成立：

```text
项目资料 -> 素材清洗 -> 关键词覆盖地图 -> 用户问题 -> 文章计划卡 -> 单篇新闻 -> 图片位 -> 审核 -> 入库 -> 导出/分发
```

要做成可卖系统，必须按以下边界开发：

```text
批量接单
单篇隔离生成
计划卡前置去重
审核低于90不入库
图片和引用可追溯
平台版二次适配
人工复核灰区
发布后效果回看
```

如果开发时跳过计划卡、关键词覆盖地图、单篇隔离上下文、独立审核模型这四个节点，系统会重新退化成“批量说明文生成器”，这是最高风险。
