# GEO内容生产系统 UI 产品规划

## 1. 设计定位

系统不是传统后台，也不是普通文章生成器。

它应当像一个“AI内容生产指挥中心”：

- 左侧管理项目和任务。
- 中间进行内容生产和编辑。
- 右侧显示审核、关键词、证据、图片和发布状态。

整体参考 GPT 的简洁工作流，但要更适合内容生产 SaaS：

- GPT 的对话效率。
- Notion 的文档编辑感。
- Linear 的任务状态感。
- 飞书多维表格的批量管理能力。

## 2. 信息架构

### 2.1 左侧导航

一级导航：

- 首页大屏
- 企业品牌库
- 品牌资料库
- 品牌文章系统
- 品牌媒体投喂
- AI诊断
- 数据中心
- 模型配置
- 系统设置

左侧应保持稳定，不随文章编辑变化。

导航顺序必须贴合生产顺序，不能按传统后台模块随意排列。用户要能从左侧自然理解：先建品牌，再准备关键词、知识库和图库，再写作审核，最后入库分发。

品牌资料库下包含：关键词、关键词库、品牌知识库、品牌图库。关键词页负责核心词和蒸馏疑问词；关键词库页负责行业拓展词。

品牌文章系统下包含：生成任务、文章审核、成品文章库。

默认写作规则由系统内置，文章批次由生成任务自然形成，不单独做主流程页面。

品牌库必须作为生产根节点。所有关键词、蒸馏词、知识库、图库、生成任务、审核记录和文章库都归属品牌。

### 2.2 中央工作区

中央区域根据页面变化：

- Dashboard：数据概览。
- 项目页：项目资料和生成任务。
- 任务页：批量队列和单篇进度。
- 编辑页：文章正文编辑器。
- 审核页：问题列表和重写建议。
- 分发页：平台版本和发布状态。

### 2.3 右侧质检面板

右侧固定承载当前内容的质量状态和下一步：

- 核心词覆盖。
- 辅助关键词覆盖。
- 标题问题化程度。
- 新闻口吻评分。
- 推荐企业出现方式。
- 品牌资产使用情况。
- 权威引证使用情况。
- FAQ状态。
- 图片状态。
- 预计豆包评分。
- 重写按钮。

右侧不是装饰，也不是无关信息拼凑。它只回答当前品牌当前步骤是否准备好、缺什么、下一步该做什么。

## 3. 关键页面

### 3.0 品牌驱动页面通用结构

每个实操页面遵循：

```text
当前品牌
主操作按钮
当前品牌数据列表
新增/导入/编辑操作区
右侧状态与下一步
```

操作和展示不能分裂。比如关键词页必须同时能看到当前品牌核心词、关键词库、蒸馏状态和添加入口；知识库页必须同时能看到品牌资产、权威引证和新增入口。

### 3.1 登录页

风格：

- 简洁高级。
- 强品牌感。
- 不要传统后台蓝白登录框。

内容：

- 系统名称：GEO内容生产中心。
- 简短说明：批量生产可被AI引用的新闻答案页。
- 登录表单。

### 3.2 Dashboard

显示：

- 今日生成篇数。
- 审核通过率。
- 平均评分。
- 待重写数量。
- 已入库文章。
- 已导出文章。
- 待分发文章。
- 最近项目。

视觉：

- 不堆卡片。
- 数据要清楚。
- 用任务流和状态条表达生产进度。

### 3.3 项目详情页

核心区域：

- 核心词。
- 推荐企业。
- 城市/行业。
- 关键词库。
- 品牌资产：1.0 直接上传或粘贴，不强制拆字段。
- 权威引证：1.0 直接上传或粘贴，用于推荐理由和可信依据。
- 图片库。
- 默认禁用规则与自定义禁用规则。
- 生成任务。

交互：

- 用户先看项目完整度。
- 系统提示缺什么资料。
- 资料不完整时允许生成测试篇，但不允许批量发布。

### 3.4 批量任务页

结构：

```text
任务目标
文章计划卡列表
队列状态
审核状态
失败重写记录
导出入口
```

每篇文章以一张任务卡展示：

- 标题问题。
- 拟定标题。
- 新闻角度。
- 选中关键词。
- 推荐企业切入方式。
- 权威引证使用点。
- 图片位置。
- 状态。
- 评分。
- 是否需要人工复核。

### 3.5 文章编辑页

布局：

```text
左：文章目录/段落导航
中：文章正文编辑器
右：质检面板
```

编辑能力：

- 重写标题。
- 重写导语。
- 重写某个小标题段落。
- 补FAQ。
- 换图片。
- 重跑审核。
- 导出当前篇。

正文编辑器要求：

- 像文档，不像代码编辑器。
- 支持标题、正文、表格、图片、FAQ、参考资料。
- 显示图片位和图注。
- 支持版本历史。

### 3.6 审核中心

用途：

- 集中处理低于90分文章。
- 处理85-89分人工复核文章。
- 查看硬失败项。

审核列表字段：

- 项目。
- 标题。
- 分数。
- 失败原因。
- 重写次数。
- 当前状态。

### 3.7 分发中心

第一版可占位，第二版实现。

平台：

- 官网。
- 新闻源。
- 博客园。
- 今日头条。
- 搜狐。
- 百家号。
- 公众号。

功能：

- 生成平台版标题。
- 生成平台版摘要。
- 调整图片。
- 选择参考资料保留方式。
- 推送草稿。
- 记录发布URL。

## 4. 视觉风格

推荐方向：

- 高级、克制、专业。
- 深色侧边栏 + 浅色内容区。
- 中央编辑区尽量干净。
- 状态和评分用克制色彩。
- 不使用夸张渐变和廉价按钮。

建议色彩：

- 背景：深灰黑侧栏 + 暖白正文。
- 主色：稳重蓝或青绿。
- 成功：绿色。
- 警告：琥珀色。
- 失败：红色。

字体：

- 中文正文优先使用系统易读字体。
- 数据和评分使用等宽数字。
- 标题要稳重，不要花哨。

## 5. 交互重点

用户不应该感觉自己在填表。

用户应该感觉：

```text
我创建了项目
系统理解了资料
系统规划了文章
系统一篇篇生产
系统审核不过就修
我只需要看结果和关键问题
```

关键交互：

- 项目完整度提示。
- 一键生成测试篇。
- 一键创建批量任务。
- 任务队列实时推进。
- 失败原因清楚显示。
- 单篇可人工介入。
- 通过文章一键导出。

## 6. UI验收标准

- 看起来像可售卖 SaaS，不像临时后台。
- 用户不用懂提示词也能完成任务。
- 文章质量状态始终可见。
- 生成流程有进度感。
- 失败原因能被普通用户看懂。
- 编辑器阅读体验舒适。
- 移动端至少能查看任务状态，编辑以桌面端为主。
