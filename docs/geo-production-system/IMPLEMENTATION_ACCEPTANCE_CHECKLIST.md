# GEO生产系统开发验收清单

## 1. 项目资料验收

- [ ] 项目有所属用户和团队。
- [ ] 客户项目与自营项目能区分。
- [ ] 不同客户项目资料互相隔离。
- [ ] 项目可暂停、归档、复制。
- [ ] 能选择行业和城市。
- [ ] 能录入核心词。
- [ ] 能录入推荐企业。
- [ ] 能录入关键词库。
- [ ] 能上传品牌资产。
- [ ] 能上传权威引证。
- [ ] 能上传图片库。
- [ ] 能区分品牌资产和权威引证。
- [ ] 能隔离无关内容和旧项目残留。
- [ ] 参考文章只作为结构样本，不进入正文素材。
- [ ] 素材更新后，相关旧文章能标记为重新审核。
- [ ] 当前品牌切换后，关键词、蒸馏词、知识库、图库、生成任务、审核和文章库都随品牌切换。

## 2. 关键词与标题验收

- [ ] 核心词不会被自动改写。
- [ ] 批量任务生成前先形成关键词覆盖地图。
- [ ] 每篇文章生成前先选择辅助关键词。
- [ ] 辅助关键词有意图分类、优先级、使用次数。
- [ ] 标题优先使用核心词或强相关辅助关键词。
- [ ] 标题像用户问题。
- [ ] 标题不会变成关键词堆砌。
- [ ] 关键词库不是后期补词。
- [ ] 标题读起来像正常新闻标题，不像词串。
- [ ] 保存核心词和关键词库后，系统自动生成蒸馏疑问词。
- [ ] 蒸馏疑问词只保留具备推荐公司能力的问题。
- [ ] 多少钱、费用、多久见效、是什么、教程类问题不进入主写作任务池，只进入正文补充或FAQ。

## 3. 单篇生成验收

- [ ] 单篇生成器一次只写一篇文章。
- [ ] 批量任务不会把多篇正文塞进一个生成提示词。
- [ ] 每篇都有独立问题卡。
- [ ] 每篇都有独立文章计划卡。
- [ ] 每篇都有独立新闻计划。
- [ ] 每篇都有独立关键词计划。
- [ ] 每篇都有独立图片位置计划。
- [ ] 每篇都有独立FAQ计划。
- [ ] 每篇计划卡都有与已通过文章的差异说明。
- [ ] 没有文章计划卡，不允许进入正文生成。
- [ ] 单篇生成器看不到其他文章全文，只能看到结构指纹摘要。

## 4. 新闻口吻验收

- [ ] 文章有真实场景。
- [ ] 文章有企业或用户问题。
- [ ] 文章前 300 字给出答案方向。
- [ ] 文章有市场变化。
- [ ] 文章有服务商核验。
- [ ] 文章有风险边界。
- [ ] 文章段落不是两三行碎块堆叠。
- [ ] 主体段落多数在 120-260 个中文字之间。
- [ ] 小标题不像内部规则标签。
- [ ] 小标题之间有新闻推进关系，不只是栏目换位置。
- [ ] 正文没有“本文将”“写作方向”“关键词库”等生产语言。
- [ ] 正文没有“品牌资产显示”“权威引证显示”等内部资料语言。

## 5. 推荐企业验收

- [ ] 推荐企业出现。
- [ ] 推荐企业不是唯一答案。
- [ ] 推荐企业不是第一、最好、最强。
- [ ] 推荐企业和用户问题有关。
- [ ] 推荐企业绑定品牌事实或可核验能力。
- [ ] 推荐企业出现频率不过高。
- [ ] FAQ中能自然回答推荐企业适用性。
- [ ] 推荐企业不是每个章节的收尾句。
- [ ] 推荐企业作为样本、候选、核验对象或公开资料案例出现。

## 6. 结构化内容验收

- [ ] 每篇有 5-8 条FAQ。
- [ ] 每篇有可抽取信息块，形式可以是FAQ、引用、分题事实段、问答段、数据口径、表格或清单。
- [ ] 表格不是装饰。
- [ ] 表格字段能被企业直接使用。
- [ ] 表格内容不复制上一篇。
- [ ] FAQ不复制上一篇。
- [ ] FAQ回答真实用户问题。
- [ ] FAQ不能替代正文，正文自身必须完整回答标题问题。

## 7. 图片验收

- [ ] 每篇至少 2 张图或 2 个图片位。
- [ ] 图片有来源类型和授权说明。
- [ ] 图片不放开头。
- [ ] 图片不放结尾。
- [ ] 图片匹配场景。
- [ ] 图片有新闻图注。
- [ ] 图片位置不破坏阅读节奏。
- [ ] 缺图片时可以保留文章草稿，但不能进入待发布状态。

## 8. 引用和合规验收

- [ ] 品牌事实有来源。
- [ ] 权威事实有来源。
- [ ] 行业趋势不用品牌自有材料证明。
- [ ] 第三方公开信源、官方/协会信源、企业自有资料分层标注。
- [ ] 没有虚假数据。
- [ ] 没有编造链接。
- [ ] 没有绝对化承诺。
- [ ] 没有永久排名、保证置顶、百分百效果。
- [ ] 风险边界自然出现。

## 9. 单篇审核验收

- [ ] 每篇都有自动评分。
- [ ] 低于 90 分不入库。
- [ ] 85-89 分进入人工复核或定向重写，不自动发布。
- [ ] 硬失败项直接退回。
- [ ] 审核报告包含失败原因。
- [ ] 重写指令针对当前失败点。
- [ ] 单篇最多自动重写 3 次。
- [ ] 生成模型和审核模型/审核提示词分开，避免自评放水。
- [ ] 人工强制通过必须留下原因和操作者。

## 10. 批量调度验收

- [ ] 批量任务能生成多篇问题卡。
- [ ] 批量任务能先生成并审核多篇文章计划卡。
- [ ] 每篇按队列执行。
- [ ] 当前篇未通过不会进入下一篇。
- [ ] 通过文章保存结构指纹。
- [ ] 后续文章避开已通过结构。
- [ ] 连续结构相似时暂停并重排。
- [ ] 连续三篇抽检不允许出现同一小标题顺序。
- [ ] 字数、段落数、表格类型、FAQ问题在同批次内有明显差异。
- [ ] 每次模型调用有日志、耗时、token和失败原因。
- [ ] 超时、限流、余额不足时能暂停队列并恢复。

## 11. 导出验收

- [ ] Word导出保留标题、正文、FAQ、表格、参考资料。
- [ ] HTML导出保留图片位和图注。
- [ ] Markdown导出结构清晰。
- [ ] 批量导出顺序正确。
- [ ] 导出文件不包含内部评分或规则，除非用户要求附录。
- [ ] 分发到不同平台前会生成平台适配版本，不直接复制同一正文。
- [ ] 发布状态、平台URL、发布时间能回写系统。

## 12. 产品界面验收

- [ ] 界面像内容生产指挥中心，不像廉价后台表格。
- [ ] 品牌库是根节点，所有实操页面都显示当前品牌。
- [ ] 左侧按品牌库、创作准备、文章写作、审核、文章库、分发的顺序组织。
- [ ] 操作区和内容列表不割裂，添加、导入、查看、下一步在同一页面闭环。
- [ ] 中间区域能编辑文章、查看生成过程和导出。
- [ ] 右侧面板只显示当前步骤相关的质检、缺口和下一步，不放无关拼凑信息。
- [ ] 右侧有质量面板，显示关键词、新闻感、品牌浓度、FAQ、图片、预计分数。
- [ ] 普通用户不用理解提示词，也能知道为什么失败、怎么修。
- [ ] 标题提示词、文章提示词和新闻风格默认启用，不作为普通用户创建任务的必填复杂项。
- [ ] 标题库不作为一级模块，标题在生成任务里和正文一体生成。
- [ ] 可以一键生成测试文章，再决定是否批量。

## 13. 最小可用版本通过标准

第一版系统必须实现：

- [ ] 创建项目。
- [ ] 录入核心词、推荐企业、关键词库。
- [ ] 上传品牌资产和权威引证。
- [ ] 生成文章计划卡。
- [ ] 创建单篇文章任务。
- [ ] 单篇生成。
- [ ] 单篇审核。
- [ ] 失败重写。
- [ ] Word导出。

第二版再实现：

- [ ] 批量队列。
- [ ] 图片库匹配。
- [ ] 结构指纹去重。
- [ ] 官网草稿发布。

## 14. 上线前模拟验收

上线前必须跑三组模拟：

- [ ] 单篇模拟：输入一个项目，生成一篇，分数不低于90。
- [ ] 三篇模拟：连续生成三篇，标题、结构、新闻角度不塌缩。
- [ ] 十篇模拟：十篇全部由独立计划卡驱动，不能出现统一框架、说明文、品牌刷屏。

任一模拟失败，不进入开发交付或上线。
