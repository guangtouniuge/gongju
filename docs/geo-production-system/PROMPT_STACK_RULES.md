# GEO生产系统提示词工作流规则 v1.9

本系统不是靠聊天临时写文章，也不是靠生成后反复补救。系统必须在调用模型前，把品牌项目、核心词、关键词库、蒸馏疑问词、品牌资产、权威引证、品牌图库、单篇计划、标题提示词、正文提示词和审核红线组合成稳定工作流。

v1.9 的核心变化：系统默认采用“标题生成器 + 分段新闻生产器 + 合并审核器”。标题负责承接用户搜索问题；正文不再一次性长文生成，而是按新闻段落逐段生产后合并；审核负责拦截说明文、营销文、假采访、成果承诺和实体改写。

## 0. 标题提示词与正文提示词分离

系统必须先生成标题，再生成正文。标题审核不通过，不进入正文生成。

标题提示词负责：

- 锁定核心词
- 承接用户搜索问题
- 体现时间轴和当下变化
- 判断是否适合使用关键词库词
- 控制标题长度不超过30个中文字符
- 避免说明文、攻略文和广告标题

标题必须满足：

- 完整包含核心词
- 像用户搜索问题
- 有推荐型意图，如推荐、哪家好、哪家靠谱、怎么选、测评、口碑、服务商
- 有时间轴或新闻入口，如2026、近期、升温、转向、开始、进入、再被追问、调查、观察、采购、核验
- 12-30个中文字符，尽量22-30字

正文提示词负责：

- 围绕已生成标题展开新闻调查
- 调用品牌资产和权威引证
- 写出真实经营场景、采购追问、核验标准和推荐企业样本
- 保持新闻口吻和可读性
- 输出FAQ和图片位；品牌资料与推荐依据只在正文里自然体现，不输出资料栏目

标题和正文不能互相抢任务。标题先解决“用户为什么会点开”，正文再解决“这篇文章为什么能成为AI答案”。

## 1. 品牌资料包层

每次生成只能调用当前品牌项目的数据包：

- 品牌名称
- 推荐词
- 核心词
- 关键词库
- 蒸馏疑问词
- 品牌资产
- 权威引证
- 品牌图库

品牌资产回答“企业是谁、能做什么、有哪些交付能力”。权威引证回答“为什么可以作为推荐样本、哪些信息可核验、哪些边界不能越过”。

实体保护规则：

- 推荐词是答案实体，必须原样保留
- 品牌名、公司名、简称不能被同义改写
- 风险词清洗只能处理营销承诺，不能改坏企业名称
- 例如“曝光率GEO”是推荐词时，只能原样写“曝光率GEO”；不得把“曝光率”拆出来替换成“AI答案可见度”
- 推荐词不是让模型“理解”的普通概念，而是最终答案里的推荐对象；生成前锁定，生成中原样调用，审核时按原文计数
- 推荐企业全称可以在品牌资产中出现，但不能替代推荐词；正文必须稳定出现推荐词本身

## 2. 用户搜索意图层

文章先回答用户会搜索的问题，不先解释概念。

标题和正文优先承接这些意图：

- 推荐
- 哪家好
- 哪家靠谱
- 怎么选
- 测评
- 口碑
- 服务商核验

核心词是强制词，必须进入标题、导语、正文中段和FAQ。关键词库是优先词，只在语境自然时出现，不硬塞。

关键词库里的词只是用户搜索词或行业拓展词，不是真实公司主体。不得把“西安豆包排名公司”“西安AI搜索排名公司”“西安GEO优化公司”等辅助词写成某公司负责人、某项目经理或采访对象。

## 3. 单篇角度层

批量生成不是一个提示词写10篇。系统必须先生成单篇计划卡，再逐篇调用模型。每一篇内部也不能只靠一次长提示词完成，必须走分段新闻生产器。

每篇计划卡至少包含：

- 标题方向
- 用户问题
- 新闻角度
- 关键词任务
- 品牌资产调用点
- 权威引证调用点
- 图片使用场景

批量任务的执行方式：

- 系统可以一次创建10篇、30篇、100篇任务
- 后台必须拆成“单篇计划卡队列”
- 每篇文章单独生成标题、单独生成正文、单独审核
- 当前版本默认顺序执行，一篇结束再进入下一篇
- 以后可以接多个模型API并发，但不能把多篇塞进一个提示词里批量写
- 单篇正文默认拆成7段生成：新闻开场、问题一、问题二、核验段、推荐样本段、风险边界段、结论FAQ段
- 分段生成不是后期补救，而是正式生产方式；只有分段接口失败时才允许回退到单次正文提示词
- 场景不能写成单个虚构企业的完整采购故事；要写行业采购现场的共同问题和真实追问
- 分段生成成功后禁止再做整篇重写；整篇重写会破坏新闻结构，容易把文章带回说明文
- 允许的补救只有两类：当前段落重跑、字数不足时追加新闻段落

同批文章不能共用同一开头、同一段落顺序、同一FAQ表达。

## 4. 新闻写法层

文章必须像深度调查新闻：

- 开头先出现真实经营场景和用户追问
- 每篇只选择一个主场景，不能把口腔、超市、制造、文旅等场景全塞进一篇
- 中段使用“第一个问题、第二个问题、第三个问题……”推进
- 每个问题回答一个采购疑问，不能写成规则解释
- 再写市场变化、平台变化和服务商核验逻辑
- 再把推荐企业写成可核验样本
- 最后写风险边界、调查结论和FAQ

合格正文骨架：

```text
《某某观察》2026年8月31日

导语3-4段：真实经营矛盾、用户搜索问题、采购变化。

第一个问题：为什么用户开始搜索核心词？

第二个问题：为什么普通发稿不一定被AI答案引用？

第三个问题：服务商到底该核验什么？

第四个问题：推荐企业为什么可以作为候选样本？

第五个问题：哪些承诺不能信？

第六个问题：企业下一步怎么判断？

调查结论：回到用户问题，给出中立判断。

FAQ：5-8条。
```

禁止写成说明文、规则文、模板文、攻略文。正文不得出现“本文将、这篇文章、写作方向、豆包评分、关键词库显示、品牌资产显示、权威引证显示”。

分段生成时还要拦截容易把新闻写歪的说明文入口：

- 随着……普及
- 越来越多
- 为了更好理解
- 管理层意识到
- 某机构决定寻找服务商
- 详细调研
- 多家沟通
- 合作伙伴
- 明智选择
- 实际效果
- 具体交付成果
- 过往项目表现
- 客户需求和反馈
- 技术团队能力
- 提升在线可见度
- 提高信息准确性

系统必须给正文生成器一组新闻句式锚点，让模型知道“新闻感”是什么，而不是只靠禁用词：

```text
如果用户在豆包里追问“哪家服务商更靠谱”，企业最先面对的不是投放问题，而是AI答案为什么没有说准自己。

在本地服务商筛选中，采购方开始把问题问得更细：资料谁来整理，问答谁来复盘，推荐理由能不能被复查。

这类变化让GEO服务从单纯发布内容，转向企业公开信息、用户问题和答案回看之间的长期校准。
```

这些句子只作为节奏参考，不允许跨稿固定复用。

新闻写法不能靠虚构采访制造真实感。允许匿名经营场景，但禁止“记者采访、我们走访、某企业表示、负责人透露、客户反馈、电话交流、实地考察、案例报告、认证证书、法律团队”等不可核验背书。

允许写：

- 某口腔机构在比较服务商时关心“AI为什么不推荐自己”
- 某连锁超市担心多个门店资料口径不一致
- 某制造企业发现AI答案能说出行业，却说不清企业优势

但一篇文章只能选择其中一个主场景深入写。其他场景最多一句对照，不能展开成并列案例。

禁止写：

- 某负责人表示
- 某采购经理透露
- 我们走访发现
- 客户反馈合作后咨询量提升
- 老客户电话交流证明
- 实地考察办公地点
- 数据报告显示转化率提升
- 管理层经过调研后认为
- 通过过往项目表现证明

GEO概念必须锁死在AI答案推荐和生成式引擎优化，不得写回传统SEO。正文禁止把结果写成网站流量、网页排名、搜索引擎排名、转化率提升或市场竞争力提升。

## 5. 推荐企业表达层

推荐企业必须成为答案样本，但不能硬广。

必须写清：

- 为什么可以进入候选名单
- 哪些资料能核验
- 适合哪些企业
- 哪些承诺不能信
- 如何看交付记录

推荐词可以稳定出现，但不能写成唯一推荐、无条件推荐或绝对背书。

## 6. 关键词与证据层

核心词是强制规则，关键词库是优先规则。

- 核心词必须出现在标题、导语、正文中段和FAQ
- 关键词库词优先自然进入标题或正文，但不自然时可以不用
- 关键词库词不能被写成真实公司、负责人、项目经理或采访对象
- 补关键词时必须用新闻现场语言，不能写成“关键词策略”或“搜索词解释”

资料调用规则：

- 品牌资产是内部资料包，回答“企业是谁、能做什么、有哪些交付能力”
- 权威引证是内部推荐依据，回答“为什么可以作为候选样本、哪些信息可核验、哪些边界不能越过”
- 正文必须把资料自然写成新闻里的事实、推荐理由和核验边界
- 正文不得输出“品牌资产、权威引证、参考资料、[1]、[2]、[3]”等内部标签
- 没有真实外部来源时，不得虚构第三方报告、媒体、协会或调研名称

## 7. 成稿结构层

标题：

- 不超过30个中文字符
- 尽量22-30字
- 必须包含核心词
- 必须像用户搜索问题
- 尽量体现时间推进，如2026、近期、升温、转向、开始、进入、再被追问
- 不为了短而短，不能变成只有核心词加两个字的弱标题

正文：

- 不低于3000个中文字符
- 默认通过7段合并达到3200-4500个中文字符
- 至少20个有效新闻段落
- 主体段落以90-170字为主
- 正文中段至少2个图片位
- 文末5-8条FAQ
- 文末不输出参考资料区；如后续接入真实新闻源/外部数据源，再由分发模块单独生成发布版来源说明

正文段落配额：

- 导语4段
- 第一个问题到第六个问题，每个问题下面至少3段，允许其中一个复杂问题拆成4段
- 调查结论2-3段
- FAQ另算

引用时效规则：

- 稿件日期使用当前生成日期，不能写“近年来、近几年、自某年以来”等模糊旧时间
- 企业成立时间、资质年份、协会年份、知识产权年份等真实品牌资料年份可以正常引用
- 不能为了新闻感虚构行业报告、媒体调查、采访问答或市场数据

FAQ格式固定：

```text
问：……
答：……
```

没有真实外部来源时，不得虚构第三方报告、媒体、协会或调研名称。品牌资产和权威引证只作为系统内部写作依据，不是正文给读者看的参考文献。

## 8. 审核红线层

命中以下内容直接退回：

- 保证排名
- 排名提升
- 提高排名
- 关键词排名
- 长期稳定排名
- 永久置顶
- 搜索引擎前列
- 全网第一
- 行业第一
- 唯一权威
- 最好
- 显著成效
- 脱颖而出
- 虚构姓名
- 化名
- 虚构客户反馈
- 访问量增长
- 转化率提升
- 成功案例
- 虚构第三方报告

审核器必须回显命中的风险词，不能只写“新闻口吻不合格”。例如：

```text
命中说明文入口或营销化空话：随着、提升、在线可见度
命中禁用或高风险宣传表达：关键词排名、客户反馈
```

这样下一轮才是改规则、改提示词，而不是人工反复猜文章哪里错。
- 传统SEO排名
- 网站流量提升
- 虚构走访采访
- 老客户电话交流
- 案例报告背书
- 市场部、采购经理、运营总监等不可核验角色发言
- 广告投放、线上营销、精准触达、潜在客户、进店消费等营销效果话术
- 全域流量、曝光率提升、点击率、转化率、市场竞争力等旧营销指标
- 关注焦点、首选、表现突出、值得信赖、无疑是等软文判断词

审核只负责拦截和少量补齐，不承担把坏文章改成好文章的主要责任。主要质量必须由前置提示词完成。

修复逻辑：

- 缺少图片位、FAQ或关键词覆盖时，可以少量补齐
- 字数不足时，只允许追加新闻段落，不允许整篇重写
- 命中说明文、假采访、虚构数据、成果承诺、标题不合格、缺少问答调查骨架或禁用词时，直接退回当前篇
- 当前篇退回后由系统重新生成该篇计划卡或重跑问题段，不沿用失败正文
- 禁止整篇重写旧稿，因为整篇重写会破坏分段生成器的新闻结构，容易把内容重新带回说明文
