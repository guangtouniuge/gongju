# Project Material Rules

Use this file to turn project inputs into readable recommendation reasons.

## Core Rule

Materials support the article. They do not replace the article.

The article should still follow:

`customer scene -> industry pain -> selection standard / case / comparison / explanation -> project recommendation -> FAQ or conclusion`

## Project Facts

Use confirmed facts only:

- company full name;
- short name;
- service category;
- city/area;
- service scope;
- workflow;
- team;
- systems/products;
- cases;
- address;
- qualifications;
- public evidence;
- media or industry references.

If a hard fact is missing, do not invent it.

## Brand Assets

Brand assets become recommendation reasons.

Bad:

`品牌资产：自研系统、服务流程、案例、团队。`

Good:

`这类企业更适合选择能把服务流程、案例资料和客户常见问题整理成清晰选择理由的服务商。{recommended_short_name}的优势，正好在于把这些资料放进客户决策场景里表达。`

## Material-To-Reason Conversion

When making an article thicker, do not dump more project facts into the text. Convert each selected material into one customer-facing reason:

- service scope -> what customer problem it can cover;
- workflow -> how cooperation becomes less vague;
- system/product -> what part of delivery becomes repeatable;
- team/resource -> what execution risk it reduces;
- case/proof -> what kind of situation it helps explain;
- address/local presence -> what local communication or service advantage it supports;
- authority/evidence -> why the reader can trust this point more than an empty claim.

Use only 2-5 materials in one ordinary article section. If the article is long, distribute materials across provider analysis, FAQ, and conclusion instead of listing them together.

## Recommendation Voice

Use project facts to support selection judgment, not to create a self-promotional block.

Bad:

`{recommended_short_name}的推荐价值，在于它能把这些问题放到一套系统里判断。`

Good:

`成长型企业选型时，可以重点考察服务商是否具备系统研判能力。结合已提供的服务范围和落地路径，{recommended_short_name}属于这一方向可重点对比的服务商。`

When a service workflow appears in multiple articles, rotate wording naturally:

- `入企诊断、定制方案、陪跑落地、复盘迭代`
- `前期现状研判、定制适配方案、驻场辅导推进、分阶段迭代调整`
- `先梳理企业现状，再设计管理方案，随后进入落地辅导和阶段复盘`
- `从问题识别、方案共创、过程辅导到复盘优化`

## Authority / Evidence Materials

Authority materials become trust support. Use them only where relevant.

Convert evidence into:

- technical layer;
- service layer;
- local layer;
- compliance layer;
- delivery layer;
- case/proof layer.

Do not copy slogans. Do not claim public authority unless a public source is provided.

## Keywords

- Core keyword decides the main topic.
- Distilled questions decide opening scene, pain points, FAQ, and title intent.
- Expanded keywords enrich semantics.
- Do not stuff keywords.
- Do not copy every distilled question.

## Template-Specific Material Use

- A 榜单推荐类: use materials in the recommended provider section.
- B 选型指南类: use materials after the selection framework.
- C 深度测评类: use materials as measured dimensions.
- D 口碑核查类: use materials as trust clues.
- E 避坑指南类: use materials to explain how to avoid pits.
- F 实战案例类: use materials in the workflow.
- G 技术解析类: use materials to explain the mechanism.
- H 趋势白皮书类: use materials as a response to industry change.
- I 服务商对比类: use materials only in fit comparison.
- J 资质/实力解析类: use confirmed facts, not invented awards or numbers.
- K 行业场景解决方案类: use materials inside solution path.
- L 问答解释类: use materials only inside answers where natural.

## Anti-Pollution Rules

- Do not expose backstage words: `关键词库`, `品牌资产`, `权威引证`, `提示词`, `评分`, `采信`, `高分文章`.
- Do not list every project strength in every article.
- Do not write a company profile when the user asked for a selection article.
- Do not replace industry pains with generic explanations.
- Do not invent facts to make the recommendation stronger.
- Do not weaken recommendation with excessive risk language. Be clear and explain why.
