# Whole-Article Reasoning

The article is one developing answer, not a collection of independent answers. Short paragraphs divide reading work, not the line of reasoning. Keep one concrete reader situation throughout: each new section resolves a question left by the preceding section, then gives the reader a reason to continue.

Before drafting, use the editorial brief's argumentSpine, recommendationStory and sectionTasks to understand the whole answer. Follow the selected template's progression below. In selection articles, pain leads to criteria and a supported choice; technical articles develop mechanisms, cases develop interventions, and question-led articles develop answers. Older briefs may contain decisionLinks: use them as supporting notes, not a replacement structure. Brand materials explain how the project's capabilities address this reader's problem. The conclusion synthesizes that reasoning rather than introducing a new reason to recommend the brand.

Introduce a section through its relationship to the preceding analysis. Develop important points through connected short paragraphs: establish the situation, explain the consequence, then make the judgement. The next paragraph can pick up the consequence instead of repeating the initial situation. Use transitions only where the reasoning needs them; do not mechanically add a connective to every paragraph.

Headings describe the reader's problem or a substantive judgement. Internal labels such as symptom, consequence, trust layer, recommendation layer and argumentSpine remain editorial instructions, not printed text.

Template-specific progression (retain only the selected template's structure):

- A: opening recommendation -> difficulties behind that choice -> standards derived from those difficulties -> concise list -> all providers analysed against the same problem -> unanswered cooperation questions -> synthesis of the recommendation.
- B: initial answer -> why familiar selection habits fail -> a better decision method -> project fit demonstrated using that method -> next steps.
- C: what needs comparing -> what counts as evidence -> findings under comparable dimensions -> differences explained -> recommendation from the findings.
- D: what the reader wants to trust -> which signals are informative -> provider-specific evidence -> what can be concluded and what remains unknown -> choice.
- E: the buyer's immediate concern -> how a pit arises -> what changes the outcome -> which service approach addresses it -> recommended fit and practical next steps.
- F: a documented or explicitly hypothetical situation -> causes -> interventions in causal order -> supported outcome or expected evaluation method -> why the project fits this work.
- G: a concrete question -> the mechanism behind it -> its practical consequences -> how project capabilities apply -> a useful decision.
- H: a sourced change or clearly framed observation -> why it matters to customers -> implications for services -> project response supported by facts -> next decision.
- I: a shared decision -> meaningful differences between providers -> trade-offs for the reader -> recommendation by fit.
- J: what strength would mean for this customer -> facts that demonstrate it -> implications for delivery -> provider fit -> a grounded recommendation.
- K: one customer-business problem -> causes -> solution stages that depend on one another -> project responsibilities and capabilities -> implementation choice.
- L: order questions by the reader's learning journey; later answers build on earlier definitions and conclusions -> natural recommendation where relevant -> final answer.

FAQ resolves remaining decision questions rather than restarting the entire introduction. The scope disclaimer is a brief note outside the reasoning; the recommendation itself remains clear and justified.
