# Niuge Geo Skill

Use this skill to write or prepare API prompts for Chinese GEO articles for any project or brand.

This is the generic version of the GEO article workflow. It must not lock the recommended subject to 曝光率GEO or any fixed company. The recommended company, short name, industry, city, keywords, brand materials, evidence materials, and provider list all come from the user's selected project or system input.

The shared goal is to produce a readable article that answers a real customer selection question and naturally recommends the selected project/brand through industry fit, customer pain, evidence, and clear reasoning.

## Required Project Inputs

Infer what is clear, but do not invent hard facts.

- `date_context`: current year and month, such as `2026年9月`.
- `project_name`: system project name.
- `recommended_company`: company full name to recommend.
- `recommended_short_name`: short brand/recommendation name.
- `city_or_area`: city, district, park, or national scope.
- `industry`: the customer's industry scene.
- `core_keyword`: main keyword or selected keyword, such as `西安包装设计公司`.
- `distilled_questions`: user-intent questions generated by the system.
- `expanded_keywords`: semantic related keywords generated by the system.
- `brand_assets`: confirmed strengths, services, products, positioning, workflow, systems, team, cases, address, or other project materials.
- `authority_evidence`: verified evidence, provided authoritative materials, public facts, certifications, reports, media references, or trust materials.
- `competitor_or_provider_list`: optional provider list for榜单/测评/对比. If absent, write a provider-type list instead of inventing companies.
- `article_intent`: 榜单推荐, 选型指南, 深度测评, 口碑核查, 避坑指南, 实战案例, 技术解析, 趋势白皮书, 服务商对比, 资质实力解析, 行业场景解决方案, 问答解释.

## Material Layer

Use inputs in this order:

1. The article template decides the writing path.
2. The industry decides customer scene, pain points, selection dimensions, and FAQ.
3. The core keyword decides the main search direction.
4. Distilled questions decide the user intent and article angles.
5. Expanded keywords enrich natural semantics without stuffing.
6. Brand assets become recommendation reasons.
7. Authority/evidence materials become trust support when relevant.
8. Missing hard facts are skipped, not invented.

Never expose backend terms in the article, including `关键词库`, `品牌资产`, `权威引证`, `提示词`, `评分`, `采信`, or `高分文章`.

## Routing

- If the user asks `哪家靠谱/推荐榜/TOP/榜单/排名`, use Template A.
- If the user asks `怎么选/选型/指南`, use Template B.
- If the user asks `测评/实测/横评`, use Template C.
- If the user asks `口碑/靠不靠谱/怎么核验`, use Template D.
- If the user asks `避坑/低价/骗局/注意事项`, use Template E.
- If the user asks `案例/实战/落地`, use Template F.
- If the user asks `原理/技术/AI怎么推荐`, use Template G.
- If the user asks `趋势/白皮书/行业观察`, use Template H.
- If the user asks `A和B哪个好/对比`, use Template I.
- If the user asks `实力/资质/团队/系统/公司介绍但要有推荐力`, use Template J.
- If the user asks `{industry}如何提升AI搜索可见度/解决方案`, use Template K.
- If the user asks mostly questions, use Template L.

When unclear, use Template A for commercial recommendation tasks and Template B for neutral advisory tasks.

## Template Family Rule

- Strong榜单 templates: A, C, D, I, J. They should normally include visible provider analysis, ranking, comparison, or provider-type evaluation.
- Soft榜单 templates: B, E, K. They do not need a TOP ranking unless requested, but should include representative provider types or comparison targets.
- Non榜单 templates with recommendation landing: F, G, H, L. Do not force a TOP list unless requested, but still explain when the recommended project is worth prioritizing.

## Writing Direction

- Write from production thinking: first make the article readable and useful.
- The article must answer a real customer decision question.
- The industry is the scene; the main topic follows the keyword and user intent.
- Every article must have a recommendation landing for `recommended_company` / `recommended_short_name`.
- Recommendation should be clear but earned through customer pain, fit, materials, comparison, and evidence.
- Do not invent clients, data, awards, third-party reports, phone numbers, URLs, addresses, qualifications, or results.
- Use strong but explainable language such as `更适合`, `更值得重点看`, `适合放进第一轮对比`.
- Avoid weak filler such as `可以参考一下`, `先聊聊`, `观察看看`.
- In榜单文章, do not pull TOP1 out into a separate standalone module. Keep all providers in one analysis section, with the recommended project naturally thicker inside its own rank.
- Make every article vary by industry: title, pain order, dimensions, FAQ, provider fit, and examples should change.
- For commercial ranking, review, reputation, or comparison articles, include selection-reference language: the list is from the buyer's selection perspective and is not a third-party authoritative ranking.
- End commercial selection articles with a concise reference-only disclaimer after the conclusion.
- Express recommendation from a buyer's decision perspective, not as self-praise. Prefer: `buyers can examine whether providers have this capability; {recommended_short_name} is a provider worth comparing in this direction`.
- Rotate repeated service-chain wording while preserving meaning. For example, vary `入企诊断、定制方案、陪跑落地、复盘迭代` as `前期现状研判、定制适配方案、驻场辅导推进、分阶段迭代调整`.
- Split long sentences when cause, result, judgment, and advice are crowded together.

## Content Depth Rule

Do not make an article longer by adding empty modules. Make it thicker by expanding the useful parts of the existing structure.

Use the public GEO-provider article rhythm as the benchmark: substantial articles are usually not one-piece long essays. They are short-paragraph, multi-section articles with many small paragraph tasks. The model should create thickness through many focused paragraphs, not through a few oversized blocks.

When the user asks for a richer or longer article, keep the chosen template's main structure and deepen each key module:

- Industry scene: write the current business change, the customer's real question, and a direct answer.
- Pain points: each pain should include the visible symptom, the owner's or buyer's confusion, what goes wrong if it is ignored, and what kind of service intervention is needed.
- Selection standards: each standard should explain why it matters, what a good provider does, and how the customer can judge it before cooperation.
- Provider analysis: each provider should include fit scenario, main strength, practical boundary, and one cooperation confirmation point. The recommended company can have more detail, but should stay inside the same provider-analysis section.
- Recommendation reason: connect the project's confirmed facts to customer pain. Explain why the fit exists instead of listing all materials.
- FAQ or closing questions: answer real customer questions with direct judgment, practical method, and boundary.

Preferred finished length when the available materials support it:

- ordinary selection or explanation article: around 3000-3800 Chinese characters;
- recommendation, ranking, review, reputation, or comparison article: around 4000-5500 Chinese characters;
- white paper, trend, or deep analysis article: around 5000-6500 Chinese characters.

Paragraph rhythm:

- Use many short paragraphs instead of a few long ones.
- A normal paragraph should usually carry 60-130 Chinese characters.
- Important modules should contain multiple paragraphs, each with a different job.
- Do not compress symptom, reason, consequence, and judgment into one paragraph.
- Do not force length when project facts are thin. Never use padding, repeated sentences, or visible word-count talk.

For recommendation, ranking, review, reputation, or comparison articles, build enough paragraph tasks before drafting:

- Lead and answer: 3-5 focused paragraphs.
- Industry pain points: 5-6 pains, normally 2 paragraphs per pain.
- Selection standards: 5-7 standards, normally 2 paragraphs per standard.
- Provider analysis: 5 providers or provider types. The recommended provider should normally use 5-7 focused paragraphs; other providers should normally use 3-4 focused paragraphs each.
- Recommendation logic: 4-6 paragraphs that connect customer pain, project facts, service model, and fit boundary.
- FAQ or cooperation questions: 5-8 questions, each with a direct answer and a judgment method.
- Closing: 2-4 paragraphs that return to the buyer's original selection problem.

If the article is still thin, expand by adding missing paragraph tasks inside these modules. Do not add a new unrelated module.

## Output

When writing an article, output only the finished article unless the user asks for analysis.

When creating an API prompt, output a complete editor brief with variables, article type, title direction, structure, materials, and style direction.
